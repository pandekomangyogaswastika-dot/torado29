### 2. Executive Q&A — LLM Tool-Calling
- **Backend**
  - New service: `services/ai_executive_qa_service.py`
  - **9 read-only tools** (no mutations): `get_kpis`, `get_sales_trend`, `get_brand_mix`, `get_anomalies`, `get_ap_aging`, `get_pl_summary`, `get_low_stock_count`, `get_outlet_drilldown`, `get_top_vendors`
  - **Two-step LLM flow**:
    1. *Tool router prompt*: input question + tool catalog → outputs `{tool, params, reason}` JSON
    2. *Answer formulator prompt*: input question + JSON tool result → outputs concise Bahasa Indonesia answer (≤4 sentences)
  - **Session memory** in MongoDB `ai_qa_sessions` collection: last 10 messages per session, TTL 30 days
  - Endpoints (all gated by `ai.exec_qa.use`):
    - `POST /api/ai/exec-qa` body `{question, session_id?}` → `{answer, tool_calls[], session_id, history[]}`
    - `GET /api/ai/exec-qa/sessions` — list user's recent sessions
    - `DELETE /api/ai/exec-qa/sessions/{id}` — delete a session
    - `GET /api/ai/exec-qa/tools` — diagnostic catalog
- **Frontend**
  - `components/shared/ConversationalQA.jsx` rewritten with tool-calling chat UI
  - Empty state: 6 starter suggestion chips (KPIs, trend, top vendors, anomalies, brand mix, low stock)
  - Chat bubble layout (user right / assistant left)
  - Each assistant bubble shows expandable "🔧 N tool calls" section with tool name + params + reason
  - "Sesi Baru" button to clear conversation
  - Verified end-to-end live in browser: question "Vendor mana yang paling banyak kita bayar bulan ini?" → real grounded answer with tool call shown

### 3. AI Vendor Recommendation
- **Backend**
  - New service: `services/ai_vendor_service.py`
  - For a given `item_id`, aggregates from `goods_receipts` + `purchase_orders`:
    - avg / last unit cost
    - lead time (PO order_date → GR receive_date)
    - GR count, total qty, last receipt date
    - vendor scorecard (Phase 9B) when present
  - **Weighted score** (0–1):
    - price 40 % (lower = higher score)
    - lead time 20 % (lower = higher score)
    - scorecard 30 % (out of 5)
    - recency 10 % (more recent = higher score)
  - **Per-vendor rationale**: 1-sentence Bahasa Indonesia generated by Gemini 2.5 Flash; falls back to deterministic stats sentence on LLM failure.
  - PR-mode: aggregates per-line recommendations + outputs a "consensus" vendor (the one most often ranked #1 across lines).
  - Endpoint: `POST /api/ai/vendor-recommend` body `{item_id} | {pr_id}` (gated by `ai.vendor_recommend.use`)
- **Frontend**
  - New reusable: `components/shared/AIVendorRecommendation.jsx` exporting:
    - `<AIVendorRecommendationInline>` — small left-bordered tile
    - `<AIVendorRecommendationModal>` — button trigger + modal with full candidate list + rationale
  - Wired in:
    - `portals/procurement/PRForm.jsx` — per-line modal trigger button next to the Trash button (only when item_id present)
    - `portals/procurement/POForm.jsx` — `Rekomendasi` button next to vendor field (uses first selected line item); plus `Rekomendasi PR` button when PO is being seeded from PRs (uses `pr_id` to compute consensus)

## ⚠️ Notes & Caveats
- **LLM model**: All Phase 9D features use `gemini-2.5-flash` via the Emergent universal LLM key. The pre-existing `categorize` LLM fallback was switched from `gpt-5-mini` to `gemini-2.5-flash`. Other features (insights, OCR) keep their existing model choices.
- **Budget caps**: LiteLLM occasionally hits per-call budget caps; the production code logs and gracefully falls back (deterministic rationale, mock answer, etc.).
- **Vendor rationale**: For PR-mode (`recommend_for_pr`), per-line rationales are skipped to keep responses snappy; only the consensus and ranked candidates are returned. Single-item mode includes rationale for each candidate.
- **Read-only Exec Q&A**: The tool catalog is intentionally read-only — the LLM cannot mutate any data. Adding new tools requires editing `TOOL_REGISTRY` in `ai_executive_qa_service.py`.
- **Confidence threshold**: AICategorizeChip default threshold is 70 %; when below, a small "saran AI tersedia (xx%) — klik untuk lihat" label appears. Set `showAlways` prop to bypass.
- **Outlet code matching**: When the LLM returns `outlet_code`, we resolve it against `outlets.code` first then fall back to first 6 chars of outlet id. If your outlets don't have `code` field set, ensure `seed_demo` populated it.
